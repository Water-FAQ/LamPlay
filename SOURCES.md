### Воспроизводимость

Сетевые запросы не содержали логин/пароль/токен пользователя. У запросов каталога был `Origin: http://lampa.mx`; поток проверялся до сегмента и через ffprobe, а не только до ответа поиска. Полные временные URL и подписи CDN не включены в публичный отчёт. Живые ссылки истекают и не должны использоваться как постоянные тестовые данные.

Каталог VeoVeo остаётся снимком из Lampac с воспроизводимым сборщиком. Его автоматическое обновление пока не развёрнуто. Изменение запасного API не обновляет справочник соответствий. Для «Братьев» наличие материала надо отличать от совпадения по названию: поиск теперь пробует оригинальное название при отсутствии KP/IMDb, но это не гарантирует наличие нужной записи.

# Источники: проверка для 0.10.0 — 03.11.2026

Проверки сделаны из среды разработки, без учётных данных пользователя и без прикладного прокси. Это не тест сети пользователя, физического LG или Safari iPhone.

## Filmix

Изучены Online Mod, Showy `m.js` → `online.js`, Dune Filmix_API 0.1.9 из сообщения https://forum.mydune.ru/viewtopic.php?p=21838 и модули [Lampac](https://github.com/lampac-nextgen/lampac/tree/main/Modules/OnlinePaid/Filmix).

- Showy использует собственный сервер, токены доступа и механизм RCH; чужой сервер не подключён к LamPlay. Проверенный маршрут fxapi без авторизации вернул «Не авторизован».
- Dune использует тот же мобильный API, `curl`, `User-Agent: okhttp/3.10.0`, версию приложения 2.2.9 и `app_lang=ru_RU`.
- На `filmixapp.cyou` оба набора параметров (старый и Dune) с User-Agent приложения вернули два сезона post/176734. Оба с браузерным User-Agent вернули пустой плейлист. Значит, в этом эксперименте различие определяется заголовком, а не версией/языком.
- `filmixapp.vip` и `fxapp.biz` с профилем приложения также вернули два сезона. Добавлены как выбираемые адреса; токены автоматически на другой домен не пересылаются.
- Из гостевого плейлиста получен MP4 480p: Range-запрос вернул HTTP206, video/mp4 и первые 1024 байта. Это не запуск в плеере LG.
- Chromium сообщил `Refused to set unsafe header "User-Agent"`; сами сетевые попытки из этого браузера закончились ERR_EMPTY_RESPONSE. Поэтому такой тест не подтверждает конкретную CORS-ошибку и не считается исправлением.
- Мобильный HTTPS API ранее вернул 503. Партнёрский API требует собственных ключей и не подключён.

### Новый путь FilmixTV

- `https://api.filmix.tv/api-fx/list?search=MobLand&limit=2`: HTTP200, корректный результат post176734 с обычным браузерным User-Agent; CORS `*`.
- `/api-fx/post/176734/video-links` и `/api-fx/post/3987/video-links`: HTTP200, сериал с озвучками/сезонами и фильм соответственно. Запросы без учётных данных, с CORS `*`.
- Выбраны ссылки 480p: HLS прочитан; Range-запросы видеосегментов обоих произведений вернули HTTP206, `video/MP2T`, первые 1024 байта, сигнатура MPEG-TS `47 40 00 10`, CORS `*`.
- В LamPlay добавлен разбор обоих форматов. Автоматический режим предпочитает FilmixTV в браузере; мобильный API сохраняется для Android и привязки. При ошибке выполняется резервный запрос вторым путём. Гостевой предел 480p; больший предел требует подтверждённого профиля.
- Живой Chromium в среде проверки вернул `Failed to fetch` для HTTPS FilmixTV; чтение реальных ответов и сегментов подтверждено отдельным HTTP-клиентом. Поэтому отсутствие CORS-барьера в ответах не выдаётся за проверенное воспроизведение в Safari/LG.

**Статус:** добавлен и проверен до реальных видеосегментов новый прямой HTTPS-путь. Полный запуск в плеере пользователя пока не подтверждён.

## VeoVeo

Уточнена схема [модуля VeoVeo](https://github.com/lampac-nextgen/lampac/tree/main/Modules/OnlineRUS/VeoVeo): API `https://api.rstprgapipt.com`, lookup из публичного каталога, `/balancer-api/proxy/playlists/catalog-api/episodes?content-id=...`.

- «Матрица» (ID15652): HTTP200, один элемент каталога. «Гангстерленд» (ID42749): HTTP200, 17 эпизодов.
- HLS обоих произведений перенаправляет на видео-CDN. Мастер и вложенный плейлист прочитаны, первые 1024 байта видеосегментов получены с HTTP206. Вложенные пути нужно разрешать относительно конечного CDN после редиректа, а не исходного API. Поэтому LamPlay передаёт исходный HLS-поток плееру и не строит неверные ссылки вариантов заранее.
- Каталожный API не вернул `Access-Control-Allow-Origin`; HLS-мастер вернул `*`. Это разные стадии доступа. Работоспособность из обычного браузера не подтверждена.
- Каталог LamPlay: 118600 записей, точный поиск по названиям/ID, разделение на 32 части. Это снимок метаданных, а не обновляемый каталог. Подробности: [data/veoveo/README.md](data/veoveo/README.md).

**Статус:** отдельный адаптер добавлен; сетевой путь до сегментов подтверждён из среды разработки. LG/iPhone требуют проверки.
