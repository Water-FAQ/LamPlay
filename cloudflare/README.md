# Cloudflare metadata Worker 0.3.0-testing

Серверная часть и подготовленный ES5-клиент для LamPlay. **lamplay.js не подключен и не изменен**, версия плагина остается 0.22.0. Публикация Worker выполняется вручную через GitHub Actions.

## Новое

- POST `/v1/rezka/login`: начальная страница, штатный вход, подтверждение сессии по ссылке выхода; не более трех запросов к одному зеркалу. Ответ `success/mirror/sessionCookie` имеет no-store, sessionCookie возвращается только вызывающему клиенту, на сервере не хранится.
- Поле `mirror` в маршрутах HDRezka/KinoTochka. Разрешены настроенный оператором origin и проверенные адреса. Дополнительные HTTPS-зеркала оператор явно добавляет в `REZKA_ALLOWED_MIRRORS` / `KINOTOCHKA_ALLOWED_MIRRORS` (origins через запятую). Неизвестное зеркало получает `mirror_not_allowed`, без запроса к нему и без передачи пароля.
- `client/transport.js` берет `rezka_host`, `rezka_login`, `rezka_password`, `kinotochka_host` из переданного `getSetting`. Сессии находятся в памяти, привязаны к зеркалу, сбрасываются при смене аккаунта или через `clearSessions`. После `source_auth_required` выполняется не больше одного входа и повторного запроса.
- `client/direct.js`: один прямой резерв для фиксированных публичных маршрутов CDNVideoHub/Filmix. Видео через Worker не загружается. `source_video_blocked` сохраняется как ошибка; не превращается в отсутствие результатов.
- `client/catalog.js`: проверяет страницы KinoTochka (максимум две одновременно), оставляет результаты с параметром file плеера; кэш страниц на время экземпляра и отдельно для каждого зеркала. Ошибка загрузки не считается отсутствием плеера.

Для будущего подключения загрузить direct.js, transport.js, catalog.js; создать клиент:

```js
var client = LamPlayMetadataClient(workerOrigin, null, {
    getSetting: function (key, fallback) { return setting(key, fallback); }
});
```

`setting` здесь — существующая функция LamPlay. Пароль и зеркало не фиксируются в клиентском файле. Вариант `directRequest(route, params, done, fail)` позволяет позже подключить существующий нативный транспорт Lampa вместо браузерного XHR. Клиент не допускает произвольные адреса прямого резерва.

Рабочий адрес сервера по умолчанию для HDRezka: standby-rezka.tv. Если пользователь явно указал другой адрес в настройках, передается именно он. Обхода защиты, подмены подписки или автоматического перехода на HTTP нет.

## Проверки

43 автоматических сценария, syntax check и dry-run. Новый серверный login-flow проверен с реальным источником в Node: подтверждены вход и поиск с сессией. Подготовленный клиент проверен реальными запросами: Worker → прямой CVH video (HTTP200), Worker → Filmix сериал (12 озвучек), Filmix заблокированный фильм (`source_video_blocked`). Проверка новых маршрутов непосредственно после публикации фиксируется в SOURCES.md/AUDIT.md.

Локальный workerd в текущей среде не запустился из-за uv_interface_addresses. Runtime smoke выполняется в GitHub Actions; это ограничение среды не заменяется заявлением об успешном локальном запуске. Воспроизведение на LG не проверено.
