8 ноября 2026. Все сетевые результаты ниже получены из среды исследования, а не с IP Cloudflare Worker и не с телевизора пользователя. Зафиксированные версии репозиториев — в [source-revisions.json](source-revisions.json), результаты HTTP без тел ответов и подписанных ссылок — в [live-probes-2026-11-08.json](live-probes-2026-11-08.json).

## Дополнение реализации 0.2.0-preparation

После уточнения объема добавлены HDRezka, Kodik, Filmix и KinoTochka: [контракт](SOURCES-API.md). В online_mod HDRezka/Kodik используют включаемый Cloudflare CORS-прокси; Filmix включает его вне Android. KinoTochka отсутствует в проверенном online_mod, но его серверная последовательность в Lampac и наш текущий адаптер дают поиск, страницу и JSON-плейлист. Поддерживаются только фиксированные операции, а не универсальный прокси.

Код не реализует вход HDRezka паролем. Разрешена явная передача существующей cookie одному настроенному HTTPS-зеркалу. Токены Kodik/Filmix передаются только в POST JSON к Worker. Сам мобильный протокол Filmix требует token в исходящем URL: он передается исключительно настроенному HTTPS API, не выводится в ошибки/логи и не используется как ключ кэша. Никаких гарантий отсутствия обработки адресов самим Cloudflare или источником это не дает. HTTP-адрес исходного Filmix не используется с личными токенами.

Новые маршруты полностью без общего кэша; для Kodik resolve максимум три последовательных подзапроса и общий срок 25 секунд. Остальные запросы ограничены 12 секундами. Это подготовленные реализации по коду и синтетическим контрактам, а не новые подтвержденные живые проверки этих источников.

## Решение для LamPlay

Использовать существующий репозиторий LamPlay, папку `cloudflare/`, отдельный ручной workflow публикации и API Token Cloudflare. Рабочий плагин 0.22.0 остается прежним. Следующая интеграция подключает Worker по источникам после проверки конкретного API и воспроизведения.

Worker закрывает межсайтовое чтение каталогов, страниц плееров и JSON со ссылками. Он не исполняет JavaScript чужих страниц, не запускает Chromium, не обслуживает видеосегменты, не обходит авторизацию или проверки человека. Получение ссылки с IP Cloudflare не гарантирует, что по ней сможет смотреть телевизор с другим IP. URL может иметь срок действия, привязку к IP, Origin, Referer или cookies.

## Архитектура запросов

1. Lampa выбирает произведение и источник. Соответствия TMDB/KP/Shikimori/AnimeLib не смешиваются.
2. Рабочий прямой адаптер сохраняется. Для предусмотренной операции можно отдельно включить Worker.
3. Worker принимает только известный маршрут и параметры: название, source ID, slug, номер страницы.
4. Назначение запроса, метод, заголовки и максимальный ответ заданы кодом. Произвольных URL, произвольных POST/login, автоматических Cookie/Authorization и клиентского IP к источнику нет. Для фиксированных операций предусмотрены POST, а существующая cookie передается только по явному полю sessionCookie к настроенному HTTPS-зеркалу HDRezka.
5. Один входящий API-запрос делает не более одного исходящего fetch, кроме нового Kodik resolve: максимум три с проверкой source rate limit на каждом шаге. Перенаправления отвергаются, ошибки/защита не маскируются пустым результатом.
6. Публичные каталоги могут недолго кэшироваться. Ссылки видео и результаты с cookies/private/no-store не попадают в общий кэш.
7. Клиент проверяет соответствие тайтла, объединяет сезоны/части, хранит состояние экрана и затем согласованно раскрывает карточки/фильтры.
8. Resolve вызывается при необходимости, а не массово для всех серий. Видео идет прямо в штатный плеер.

Worker не является местом для алгоритмов интерфейса: объединение сезонов, история, прогресс, выбранная озвучка и atomic reveal остаются в LamPlay. При сетевом отказе нельзя окрашивать источник как «тайтл отсутствует»: это неизвестный результат.

## Кэш и нагрузка

Подготовленные TTL: поиск/эпизоды AnimeLib и каталог CVH — 60 секунд, videoServers — 300 секунд; HTML AnimeGO, embed Aniboom, плееры серии AnimeLib и `/video` CVH — без общего кэша. Клиент получает `Cache-Control: no-store`, edge cache хранит только допустимые копии без CORS для конкретного пользователя. Ключ включает версию и полный нормализованный upstream URL. Ошибки не кэшируются.

Cache API Cloudflare локален для дата-центра; это не единый мировой каталог. Cache-hit по-прежнему является входящим запросом Worker и расходует дневную квоту. Кэш экономит запросы к источнику. Параллельные одинаковые miss могут дать несколько запросов: глобальный lock не реализован. Кэш экрана LamPlay остается первым уровнем экономии.

Встроенный Rate Limiting приблизительный, отдельно по локациям. Два binding ограничивают клиента и совокупные обращения к источнику. IP выбран как простой контроль злоупотреблений для публичного клиента без аккаунтов, но при общем NAT может ограничить нескольких людей. Это не защита от распределенной атаки и не строгий дневной бюджет. CORS также не является авторизацией: обычный HTTP-клиент может подделать Origin.

## Стоимость и инфраструктура

По официальным лимитам Workers Free: 100 000 входящих запросов в сутки на аккаунт, 10 мс CPU на вызов, 50 subrequests на вызов. Сетевое ожидание не считается CPU, но разбор больших документов считается. Пакет ограничивает ответ 1 MiB и полный запрос 12 секундами. Сборка не измеряет CPU в реальном Cloudflare; метрики необходимо проверить на пробном включении.

Пример нагрузки, не прогноз: 100 открытий по 20 запросов метаданных — около 2000 вызовов; 100 открытий с полным обходом 1180 серий — минимум 118 000 вызовов только на сериальные плееры. Дополнительно возможны preflight OPTIONS. Вывод: последовательный массовый обход AnimeLib нельзя просто перенести в Worker.

На бесплатном плане отдельная аренда сервера и покупка домена не нужны. Квота относится к аккаунту, не каждому Worker. Платный Workers начинается от $5/месяц с отдельными включенными объемами и доплатой; пакет не переключает тариф и ничего не оплачивает. Лимиты и цены могут меняться.

Для российских сетей есть отдельный практический риск. Cloudflare официально сообщает о замедлениях у российских ISP. Проверить нужно сам workers.dev URL и ответ каталога существенно больше 16 KiB с сети ТВ/телефона; успех `/health` в несколько байт недостаточен. Собственный домен поверх того же Cloudflare не гарантирует устранения ограничения. До проверки не делать Worker обязательным для всех пользователей.

## Что остается проверить до рабочего включения

Реальное развертывание с токеном владельца; маршрут из IP Cloudflare к каждому API; лимит CPU и реальное кэширование; доступ из сети пользователя, в том числе большие ответы; воспроизведение прямых ссылок на LG/WebOS; отмена при закрытии экрана; свежие ID AnimeGO/Aniboom; стоимость порционного получения плееров AnimeLib; корректные связи mali; поведение при устаревании ссылок и 429/403. Готовность этого пакета к пробной публикации не означает, что перечисленные проверки уже пройдены.
