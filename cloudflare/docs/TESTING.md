# Тестирование после пробной публикации

Сначала выполнить SETUP.md и развернуть Worker в своем аккаунте. Текущий плагин не меняется. Пакет по умолчанию не включает ни один источник; включать по одному через ENABLED_SOURCES и ручную публикацию. /health показывает включенные имена.

## Автоматические проверки без аккаунта

В `cloudflare/`:

```bash
npm ci
npm run check
npm test
npm run dry-run
```

GitHub Actions дополнительно запускает локальный workerd и проверяет POST/preflight/JSON/rate bindings без запросов к внешним источникам и без секретов публикации.

## Осторожный probe своего Worker

Подготовлен `scripts/probe-worker.mjs`. Он делает последовательные запросы метаданных, не публикует Worker, не запускает видео и не вызывает привязку Filmix. В отчете только имя теста, HTTP-статус, код ошибки, число результатов и названия качеств; токены, cookies и видеоссылки не печатаются.

В PowerShell из папки cloudflare установить только фактический origin и нужный источник:

```powershell
$env:LAMPLAY_WORKER_URL = 'https://ВАШ-ОПУБЛИКОВАННЫЙ-WORKER'
$env:LAMPLAY_TEST_SOURCES = 'rezka,filmix,kinotochka'
node scripts/probe-worker.mjs
```

Адрес не содержит /health или /v1. Стандартный тестовый Origin — http://lampa.mx; при необходимости изменить LAMPLAY_TEST_ORIGIN на реальный разрешенный origin приложения. Сначала можно выбрать один источник, а не всю строку.

Для Kodik API скрипт читает **KODIK_TEST_TOKEN** из локального окружения. Для полного resolve — **KODIK_TEST_PATH**, путь конкретной серии из найденного плеера. Для mobile Filmix — **FILMIX_TEST_TOKEN** и **FILMIX_TEST_DEVICE_ID** из своего устройства/аккаунта. Если значения не заданы, соответствующие тесты пропускаются. Это токены источников, а не CLOUDFLARE_API_TOKEN. В чат и Git они не передаются.

Для HDRezka с существующей сессией отдельно использовать POST page/episodes/stream по SOURCES-API.md; общий probe не собирает cookies и не запрашивает пароль. Создание запроса привязки Filmix — отдельное явное действие, не автоматический тест.

## Что считать успехом

1. Ответ HTTP200 имеет правильный тип и структуру, тайтл/ID соответствуют выбранной карточке. Поисковый HTML и JSON следует разбирать так же, как штатный адаптер, а не просто смотреть на статус.
2. Список сезонов/переводов соответствует источнику; количество строк плейлиста не принимается за число уникальных серий.
3. Kodik возвращает results либо found:false; отказ токена отличается от сетевого 403. Затем конкретный resolve дает quality без выполнения внешнего JS.
4. Filmix показывает доступ только своего аккаунта, без выдуманного повышения качества. Если mobile HTTPS не работает, тест отметить неуспешным, не переключаться молча на HTTP.
5. В KinoTochka ссылка .txt/.json проверена и закреплена в конфигурации; произвольный URL извне не разрешается.
6. Полученную ссылку проверить штатным плеером на ТВ. Worker не должен загружать mp4/m3u8/segments вместо плеера.
7. В сети пользователя проверить каталог больше 16 KiB: короткий health не исключает ограничений Cloudflare со стороны ISP.
8. Проверить 403/429, отмену при выходе из экрана и устаревание ссылки. Ошибка Worker не превращается в «источник пуст».

При source_disabled включить только нужный источник и повторить ручную публикацию. При origin_required/denied проверить протокол и Origin клиента. При upstream_redirect подтвердить новое зеркало и изменить серверную настройку. При upstream_denied не менять пароль автоматически и не обходить защиту сервиса. До успешного теста в аккаунте/сети пользователя рабочую сборку LamPlay не подключать к Worker.
